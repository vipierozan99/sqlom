### ANALYTICAL CEILINGS (sqlite decomposition) — RE-RUN
Corrected: Ceiling 1 previously summed the surviving stages to get the floor and
then divided that into the separately *measured* pipeline, so the unattributed
composition cost (~6%) was silently credited to the speedup. Published 1.51x;
on the same data the correct top-down figure is 1.42x, and this re-run on the
current box gives 1.37x.

   sqlite3 fetch (tuples)                81.68    816.8   60.6%
   hydrate tuples -> slotted objects     16.70    167.0   12.4%
   orjson.dumps + per-row _default       28.82    288.2   21.4%
   measured full pipeline               134.86   1348.6  100.0%

==========================================================================
CEILING 1: driver constructs slotted objects directly
==========================================================================
  removable: the row tuple (19.81 us) and the Python
             hydration loop (16.70 us)
  NOT removable: creating 400 Python values (54.36 us), the statement (7.50 us),
             and the JSON step (28.82 us)

  stage sum 127.20 us vs measured pipeline 134.86 us -> +7.66 us unattributed
  (5.7% of the request is composition cost the isolated stages
   do not capture; it is left in the floor rather than assumed removable)

  optimistic floor: 98.34 us vs 134.86 us now  ->  1.37x
  = measured 134.86 - tuple 19.81 - hydration 16.70
  (optimistic because a native builder still allocates the object and
   writes its slots; it does that in C rather than bytecode, not for free)

==========================================================================
CEILING 2: Rust extension
==========================================================================
  orjson is ALREADY Rust and sqlite3 is already C, so a Rust rewrite can
  only replace the 16.70 us hydration loop and the per-row
  _default callback inside the 28.82 us JSON step.

  (a) Rust mapper still returning Python objects:
      bounded by ceiling 1 — 1.37x — because creating 400 Python
      values costs 54.36 us (40% of the request) and is unavoidable
      the moment the API hands back objects with Python field values.

  (b) Rust returning JSON bytes, no Python objects at all:
      Python value creation vanishes too. Measured anchor for exactly
      that shape — sqlite's json_group_array, all work below Python:
      63.45 us vs 134.86 us  ->  2.13x
      A Rust extension doing rows->JSON could approach this, and it is
      already reachable today in SQL with no Rust at all.
